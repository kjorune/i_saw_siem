발신 추정식은 다음과 같다.

```text
sender_verified =
  lower(trim(email.from)) = lower(trim(LDAP.email))
  AND email.user = LDAP.user_id
```

LDAP는 이벤트 발생 월의 스냅샷을 사용했다. 수신자는 `to`, `cc`, `bcc`를 `;`로 분리하고 빈 문자열을 제거했다. 주소 도메인이 대소문자 구분 없이 정확히 `dtaa.com`일 때만 내부로 처리했다.

## 6. 사용자×일 기준선과 robust z-score

현재 날짜와 미래 날짜를 제외하고 사용자별 이전 30개 관찰일만 사용했다.

```text
prior = 같은 사용자의 현재 날짜 이전 최대 30개 관찰일
center = median(prior)
robust_scale = (P75(prior) - P25(prior)) / 1.349
robust_z = (current - center) / robust_scale
```

IQR이 0인데 현재값이 중앙값보다 크면 6으로 처리했다. 이전 관찰일 7일 미만은 z-score를 0으로 두고 `COLD_START`, 7~29일은 `WARMING`, 30일 이상은 `MATURE`로 관리했다. 이벤트 수준 대용량 기준에서는 median과 MAD를 직접 사용하고, 사용자×일에서는 계산 안정성과 대규모 rolling 처리를 위해 median/IQR 기반 강건 z-score를 사용했다.

## 9. 점수 신뢰도

위험점수와 별도로 다음과 같이 계산했다.

```text
feature_coverage = 다중 로그 사용 가능 시 1.0, 아니면 0.75
baseline_factor = min(observation_days_before, 30) / 30
source_quality = 0.90
score_confidence = 100 × (0.40×feature_coverage + 0.35×baseline_factor + 0.25×source_quality)
```

`source_quality=0.90`은 파싱·조인 품질은 높지만 방향·size 단위·파일 의미가 완전히 명세되지 않은 점을 반영한 설계값이다. 정답 기반 추정치는 아니다.

## 12. 근거의 강도와 해석 한계

| 근거 수준 | 예 | 해석 |
|---|---|---|
| 직접 관찰 | 외부 주소, 첨부 수, BCC, 시각, size | 해당 필드가 로그에 존재한다는 사실 |
| 규칙 기반 추론 | 내부 사용자 발신 추정, 신규 목적지, 개인 기준 급증 | 정의한 규칙 아래의 후보 |
| 시퀀스 후보 | 파일 이벤트 후 외부 첨부메일 | 시간적 선후관계이며 인과관계는 아님 |
| 확인 불가 | 실제 파일 내용, 기밀 여부, 전달 성공, 악의성 | 추가 원본 증거 필요 |

오탐을 줄이려면 승인 수신처 목록, 근무표, 첨부 해시·등급, 메일 전달 상태, 업무 승인 기록이 필요하다. 미탐을 줄이려면 링크 공유, 웹 업로드, USB 복사, 암호화 압축파일과 개인 클라우드 로그를 결합해야 한다.

## 13. 재현성과 검증

- 원본 DB는 읽기 전용 연결로 사용했다.
- 신규 목적지와 기준선은 현재 이벤트·현재 날짜 이전 기록만 참조한다.
- 이벤트→사용자×일 외부메일 수 재집계가 일치한다.
- S3 완료는 파일 이벤트가 메일보다 앞서는 경우만 유지한다.
- 위험점수와 신뢰도 점수는 별도 컬럼이다.
- 출력에는 실제 이메일 주소·사용자 이름·본문이 없다.

검증 결과는 `outputs/validation_results.json`, 분포 임계값은 `outputs/thresholds.json`, 지표 장표는 `outputs/user_indicator_details.parquet`에서 확인할 수 있다.
