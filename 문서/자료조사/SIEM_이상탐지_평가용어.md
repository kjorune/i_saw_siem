# SIEM 이상탐지·평가 용어 정리

## 가장 쉬운 핵심 정리

```text
이상도: 평소와 얼마나 다른가?
위험점수: 실제로 얼마나 위험해 보이는가?
경보: 시스템이 위험하다고 알린 것
정탐: 공격을 제대로 잡은 것
오탐: 정상인데 공격으로 잘못 잡은 것
미탐: 공격인데 놓친 것
```

## 서술 순서

```text
로그 → 특징 집계 → 기준선 → Z-score → 이상점수
→ 가중치 → 위험점수 → 경보 → 정탐·오탐·미탐 평가
```

## 1. 로그(Log)

시스템에서 발생한 행동을 기록한 자료입니다.  
예: `user01이 새벽 2시에 로그인에 실패했다.`

## 2. 이벤트(Event)

로그에서 분석할 만한 행동 하나를 뽑아 정리한 것입니다.  
예: `사용자=user01, 행동=로그인, 결과=실패`

## 3. 특징(Feature)

위험한 행동인지 판단하기 위해 로그에서 골라낸 값입니다.  
예: 로그인 실패 횟수, 다운로드 용량, 접속한 서버 수

## 4. 특징 집계

일정한 시간 동안 발생한 행동의 횟수나 양을 계산하는 것입니다.  
예: `user01의 최근 1시간 로그인 실패 횟수 = 10회`

## 5. 분석 단위

누구 또는 무엇을 기준으로 행동을 계산할지 정하는 것입니다.  
예: 사용자별 분석, 서버별 분석, IP별 분석

## 6. 기준선(Baseline)

사용자나 서버의 평소 행동 범위입니다.  
예: `user01은 평소 하루에 파일을 평균 10개 다운로드한다.`

## 7. 평균(Mean)

여러 값을 모두 더한 뒤 값의 개수로 나눈 값입니다.  
예: `8개, 10개, 12개의 평균 = 10개`

## 8. 표준편차(Standard Deviation)

값들이 평균 주변에서 얼마나 자주 크게 변하는지 나타냅니다.  
예: 매일 9~11개면 작고, 매일 1~20개면 큽니다.

## 9. Z-score

현재 값이 평소 평균에서 표준편차 몇 개만큼 떨어졌는지 나타냅니다.  
예: `평균 10, 표준편차 5, 현재 25 → Z-score = 3`

## 10. 절댓값 Z-score

평균보다 높거나 낮은 방향을 빼고, 떨어진 거리만 보는 값입니다.  
예: `Z=3`과 `Z=-3`은 모두 `|Z|=3`입니다.

## 11. Z-score 해석

`|Z|<1` 정상, `1≤|Z|<2` 약한 변화, `2≤|Z|<3` 이상징후, `|Z|≥3` 강한 이상입니다.  
예: `|Z|=3.2 → 평소와 매우 다른 행동`

> 위 구간은 OT 자료의 예시이며, 실제 기준은 로그 분포와 검증 결과에 따라 조정합니다.

## 12. 신규성

과거에 없었던 IP, 기기 또는 자원이 새로 나타났는지 확인하는 것입니다.  
예: 최근 30일에 없던 IP로 로그인하면 `신규 IP`입니다.

## 13. 이상행동(Anomaly)

평소 기준선과 다른 행동이며, 반드시 공격이라는 뜻은 아닙니다.  
예: 직원이 처음으로 새벽 2시에 로그인했습니다.

## 14. 이상도·이상점수(Anomaly Score)

행동이 평소와 얼마나 다른지를 숫자로 나타낸 것입니다.  
예: 다운로드량이 평소보다 크게 증가하여 이상점수 80점

## 15. 위협(Threat)

시스템이나 정보를 실제로 해칠 가능성이 있는 대상이나 행동입니다.  
예: 탈취 계정으로 관리자 권한을 얻고 개인정보를 내려받음

## 16. 가중치(Weight)

중요한 위험 신호에 더 큰 비중을 주는 값입니다.  
예: 신규 IP 20%, 권한 상승 30%, 대량 다운로드 50%

## 17. 점수 기여도

각 이상 신호가 최종 위험점수에 더한 점수입니다.  
예: 신규 IP `+20점`, 권한 상승 `+30점`

## 18. 위험점수(Risk Score)

여러 이상 신호와 중요도를 합쳐 실제 위험 정도를 나타낸 점수입니다.  
예: 신규 IP와 대량 다운로드가 함께 발생해 위험점수 85점

## 19. 신뢰도(Confidence)

시스템이 자신의 판단을 얼마나 확신하는지 나타냅니다.  
예: `공격일 가능성을 모델이 90%로 판단`

## 20. 임계값(Threshold)

몇 점 이상일 때 경보를 울릴지 정한 기준입니다.  
예: 위험점수 70점 이상이면 경보 발생

## 21. 경보(Alert)

시스템이 위험하다고 판단해 보안 담당자에게 알린 결과입니다.  
예: `user01 계정 탈취 가능성—위험점수 85점`

## 22. 사건(Incident)

서로 관련된 여러 로그와 경보를 하나의 보안 문제로 묶은 것입니다.  
예: 해외 로그인부터 개인정보 유출까지를 사건 1건으로 처리

## 23. 상관분석(Correlation)

사용자·시간·IP 등을 기준으로 여러 행동을 하나의 흐름으로 연결합니다.  
예: 해외 로그인 → 권한 상승 → DB 접근 → 대량 다운로드

## 24. 정탐(True Positive, TP)

실제 공격이 발생했고 시스템도 경보를 울린 경우입니다.  
예: 계정 탈취 공격을 시스템이 탐지했습니다.

## 25. 오탐(False Positive, FP)

정상 행동인데 시스템이 공격이라고 잘못 경보한 경우입니다.  
예: 정상적인 백업 작업을 정보 유출로 판단했습니다.

## 26. 미탐(False Negative, FN)

실제 공격이 발생했지만 시스템이 경보를 울리지 않은 경우입니다.  
예: 개인정보가 유출됐지만 시스템이 발견하지 못했습니다.

## 27. 정상 판정(True Negative, TN)

정상 행동에 대해 시스템도 경보를 울리지 않은 경우입니다.  
예: 평소와 같은 출근 시간 로그인을 정상으로 판단했습니다.

## 28. 정밀도(Precision)

발생한 경보 중 실제 공격이었던 비율입니다.  
예: 경보 10건 중 공격이 8건이면 정밀도는 80%입니다.

## 29. 재현율(Recall)

실제 공격 중 시스템이 찾아낸 비율입니다.  
예: 공격 10건 중 9건을 찾았다면 재현율은 90%입니다.

## 30. 오탐률(False Positive Rate, FPR)

전체 정상 행동 중 시스템이 잘못 경보한 비율입니다.  
예: 정상 행동 1,000건 중 10건을 경보하면 오탐률은 1%입니다.

## 31. 미탐률(False Negative Rate, FNR)

전체 실제 공격 중 시스템이 놓친 비율입니다.  
예: 공격 10건 중 2건을 놓쳤다면 미탐률은 20%입니다.

## 32. 정확도(Accuracy)

전체 판단 중 공격과 정상을 올바르게 판단한 비율입니다.  
예: 100건 중 95건을 맞혔다면 정확도는 95%입니다.

## 33. F1 점수(F1-score)

정밀도와 재현율을 함께 평가한 균형 점수입니다.  
예: 경보도 정확하고 공격도 잘 찾아야 F1 점수가 높습니다.

## 34. 라벨(Label)

각 데이터가 실제 공격인지 정상인지 표시한 정답입니다.  
예: `confirmed_malicious`, `confirmed_benign`, `unknown`

## 35. 클래스 불균형

정상 데이터가 공격 데이터보다 훨씬 많은 상태입니다.  
예: 정상 로그 99,900건, 공격 로그 100건

## 36. 탐지 지연시간

공격이 발생한 뒤 경보가 울릴 때까지 걸린 시간입니다.  
예: 02:00 공격, 02:07 경보 → 탐지 지연시간 7분

## 가장 헷갈리는 차이

```text
Z-score   = 평균에서 얼마나 떨어졌는가?
이상점수  = 평소와 얼마나 다른가?
위험점수  = 여러 증거를 합쳤을 때 얼마나 위험한가?
경보      = 위험점수가 기준을 넘었다고 알린 결과
평가지표  = 그 경보가 실제로 정확했는지 확인한 결과
```

```text
정밀도 = 발생한 경보를 얼마나 믿을 수 있는가?
재현율 = 실제 공격을 얼마나 놓치지 않았는가?
정확도 = 공격과 정상을 포함해 전체 판단을 얼마나 맞혔는가?
```

## 정탐·오탐·미탐 한눈에 보기

| 실제 상황 | 시스템이 경보를 울림 | 시스템이 경보를 울리지 않음 |
|---|---|---|
| 실제 공격 | 정탐(TP) | 미탐(FN) |
| 정상 행동 | 오탐(FP) | 정상 판정(TN) |
