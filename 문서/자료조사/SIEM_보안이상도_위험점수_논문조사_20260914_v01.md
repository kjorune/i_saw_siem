# 보안 이상도 및 위험 스코어링 최근 논문 조사

## 핵심 결론

보안 로그의 **이상도**, **공격 가능성**, **업무 위험도**, **대응 우선순위**는 같은 값이 아니다. 최근 연구를 종합하면 이 네 값을 분리해 계산하고, 최종 위험점수에는 각 근거의 기여도와 모델의 불확실성을 함께 표시하는 설계가 가장 일관된다.[^1][^2][^3]

가장 현실적인 SIEM PoC 구조는 다음과 같다.

```text
로그 정규화
→ 사용자·자산·시간창별 특징 집계
→ 개인/집단 기준선과 비교한 이상도
→ 반복·시퀀스·신규 관계·외부 위협 신호 결합
→ 공격 가능성 및 신뢰도 보정
→ 자산 중요도와 업무 영향 반영
→ 설명 가능한 위험점수와 조사 순위
→ 분석가 판정으로 재검증 및 개선
```

위험점수는 처음부터 자동 차단 기준으로 사용하기보다 **분석가가 먼저 볼 대상을 정하는 순위값**으로 사용하는 편이 안전하다. 최신 RBA 연구도 위험 기반 경보를 고정 임계값의 이진 판단보다 연속적인 우선순위 문제로 평가한다.[^4]

## 1. 전문가 네 관점의 합의

### 관점 1: 이상탐지·기준선

Z-score는 횟수나 용량이 평균에서 얼마나 떨어졌는지 설명하기 쉬우나, 모든 로그 이상을 표현하지 못한다. 최신 연구에서는 시퀀스 편집거리, 계층적 실행 문맥, 분포 변화, 그래프 관계 등 데이터 구조에 맞는 이상도를 함께 사용한다.[^5][^6]

따라서 테이렌 PoC에서는 다음처럼 나누는 것이 적절하다.

| 신호 종류 | 권장 계산 방식 | 예시 |
|---|---|---|
| 수치 변화 | Z-score, Robust Z-score, 분위수 | 로그인 실패·다운로드량 증가 |
| 신규 관계 | 과거 존재 여부 | 신규 IP·신규 자산·신규 DB |
| 행동 순서 | 시퀀스 거리·세션 모델 | 실패→성공→권한 상승 |
| 분포 변화 | 엔트로피·KL divergence | 접속 IP·포트 분포 변화 |
| 관계 변화 | 사용자–IP–자산 그래프 | 처음 나타난 접근 경로 |

### 관점 2: 위험점수·확률 보정

모델의 이상점수를 그대로 공격 확률이라고 부르면 안 된다. 로그 이상탐지 모델이 틀린 답에도 높은 확신을 보일 수 있다는 최근 연구가 있어, 별도의 확률 보정과 오답 신뢰도 검사가 필요하다.[^7]

권장 출력값은 다음 다섯 개다.

1. 행동 이상도: 평소와 얼마나 다른가
2. 공격 가능성: 관측 신호가 공격과 얼마나 일치하는가
3. 모델 신뢰도: 그 판단을 얼마나 믿을 수 있는가
4. 업무 위험도: 중요한 자산과 데이터에 어떤 영향을 주는가
5. 최종 우선순위: 분석가가 언제 조사해야 하는가

### 관점 3: 평가·통계

정상 로그가 압도적으로 많은 환경에서는 정확도와 weighted-F1이 희귀 공격의 실패를 숨길 수 있다. 2026년 9월 공개된 7종 네트워크 클래스 연구에서 Random Forest의 weighted-F1은 0.9815였지만 희귀 Infiltration 클래스 F1은 0.2106이었다.[^8]

따라서 최소 평가표에는 다음을 함께 기록해야 한다.

- 클래스별 Precision·Recall·F1과 macro-F1
- PR-AUC와 확률 보정 지표 Brier score 또는 ECE
- 오탐률과 하루 절대 오탐 건수
- 사건·시퀀스 단위 재현율
- 최초 이상행동부터 최초 올바른 경보까지의 지연시간
- 분석가가 하루 처리할 수 있는 상위 K개 경보의 Precision@K

### 관점 4: SOC 운영·반박 검토

위험점수의 목적은 모든 경보를 자동 삭제하는 것이 아니라 제한된 분석 시간을 중요한 사건에 먼저 배분하는 것이다. Microsoft의 2026년 사전공개 연구는 1,000개 고객 조직 전문가 평가에서 사건 순위 모델이 Precision@10 92.8%를 기록했고, 473,000개 조직-일 큐에서 심각도 정렬 대비 상세 경보 상호작용이 5.8%, 상세 보기 이벤트가 17.5% 증가했다고 보고했다.[^9]

다만 상호작용 증가는 공격 탐지나 피해 감소를 직접 증명하지 않는다. 사용자가 상위 경보를 더 많이 열었다는 운영 행동의 증거이며, 실제 정탐률·미탐률·대응 결과는 별도 검증해야 한다.

## 2. 새로 확인한 핵심 논문

### 2.1 Detecting anomalies in log files using the Damerau–Levenshtein distance metric

- 상태·발행일: **동료평가, 2026년 1월 10일**
- 핵심: 로그를 템플릿 ID 시퀀스로 바꾼 뒤 가중 Damerau–Levenshtein 거리로 정상 시퀀스와 다른 정도를 계산한다.[^5]
- 데이터: HDFS, BGL, Thunderbird/PBS_MOM 및 비공개 산업 데이터
- 확인 수치: BGL에서 비지도 라벨러 단독 F1은 0.565였고, 전문가가 오탐 15개 클러스터와 미탐 9개 클러스터를 수정한 뒤 F1이 0.90을 넘었다.[^5]
- 적용: `로그인 실패→성공→자원 접근`처럼 순서가 중요한 신호에 사용 가능
- 한계: 성능이 클러스터 설정과 전문가 개입에 민감하며, 수치형 속성 이상을 직접 다루지 않는다.

### 2.2 KRONE: Scalable LLM-Augmented Log Anomaly Detection via Hierarchical Abstraction

- 상태·발행일: **ICDE 2026 accepted 표기의 arXiv 사전공개, 2026년 2월 7일**
- 핵심: 평면 로그를 실행 계층으로 복원하고 작은 실행 단위의 문맥 이탈을 탐지하며, 어려운 일부 사례에만 LLM을 사용한다.[^6]
- 데이터: 공개 로그 벤치마크 3종과 ByteDance Cloud 산업 데이터 1종
- 확인 수치: 논문 실험 범위에서 F1은 82.76%에서 92.83%로 10.07%p 증가했고, LLM 호출은 테스트 사례의 1.1~3.3%였다.[^6]
- 적용: 전체 로그를 LLM으로 보내지 않고 어려운 사건만 보조 분석하는 비용 절감 구조
- 한계: 실행 계층 추출이 틀리면 이상도도 흔들리며, 해당 수치를 사용자 위험점수 성능으로 일반화할 수 없다.

### 2.3 HSMLog: Small Language Model-Assisted Hardware Security Module Log Anomaly Detection with Behavioral Analysis

- 상태·발행일: **arXiv 사전공개, 2026년 8월 30일**
- 핵심: HSM 이벤트의 슬라이딩 창을 평가하고 정책·과거 의심 키·주변 로그로 후보 경보를 다시 검증한다.[^10]
- 데이터: 실제 산업 HSM 배경 로그와 산업 파트너가 설계해 주입한 이상 시나리오
- 확인 수치: 정밀도 98.97%, 재현율 96.00%, F1 97.46%; 정책만 사용한 경우 정밀도는 100%였으나 재현율은 21%였다.[^10]
- 적용: 통계 이상도와 보안정책을 단계적으로 결합하는 구조
- 한계: 단일 HSM 환경과 주입형 공격이며, 정책 강화로 오탐을 줄이면 미탐이 크게 증가할 수 있음을 논문 자체가 보여준다.

### 2.4 Employing multi-format log analysis to detect DDoS attacks in SDN

- 상태·발행일: **동료평가, 2026년 3월 28일**
- 핵심: 세션 로그와 flow table의 엔트로피로 1차 후보를 만들고 KL divergence로 다시 확인한다.[^11]
- 대상: Software-Defined Network의 TCP SYN flood 및 IP·포트 무작위화 공격
- 확인 수치: TCP SYN flood TPR 98.5%, 무작위화 공격 TPR 96.0%, FPR 1.5%.[^11]
- 적용: 단일 점수가 아니라 서로 다른 두 지표로 경보를 재확인하는 사례
- 한계: DDoS 전용이며, 공격 비율이 낮은 실제 환경에서는 FPR 1.5%도 많은 오탐을 만들 수 있다.

### 2.5 Too Sure to Be Safe: Model Calibration for Reliable Log Anomaly Detection

- 상태·발행일: **ICDM 2026 accepted 표기의 arXiv 사전공개, 2026년 8월 18일**
- 핵심: 탐지 모델이 틀린 답에도 지나치게 높은 확률을 주는 과신 문제를 분석하고 사후 보정 방법 LoRD를 제안한다.[^7]
- 데이터: 대규모 로그 벤치마크 4종과 복수 언어모델 기반 탐지기
- 적용: `이상점수`, `공격확률`, `모델 신뢰도`를 별도 칼럼으로 관리할 근거
- 한계: 최종 학회 출판본 확인이 필요하며, ECE·Brier 개선만으로 모든 오답의 과신이 해결됐다고 볼 수 없다.

### 2.6 A two-stage generative-AI fusion intrusion detection system for calibrated and reliable cloud security

- 상태·발행일: **동료평가, 2026년 5월 5일**
- 핵심: 1단계에서 공격 여부, 2단계에서 공격 종류를 분류하고 검증 데이터로 확률과 임계값을 보정한다.[^12]
- 확인 수치: UNSW-NB15에서 정확도 94.04%, macro-F1 0.9346, Brier 0.1355; NSL-KDD에서는 정확도 77.74%, macro-F1 0.6035, Brier 0.3986이었다.[^12]
- 차이의 이유: 두 데이터셋의 클래스 구성·분포·공격 난이도가 달라 동일 모델의 결과가 크게 달라졌다.
- 한계: NSL-KDD의 희귀 Privilege 클래스 F1은 0.2667, Access 클래스 recall은 0.1859로 전체 정확도가 희귀 공격 미탐을 숨겼다.[^12]

### 2.7 Integrated risk scoring and exploit prediction for cyber-physical power system vulnerabilities

- 상태·발행일: **동료평가, 2026년 2월 6일**
- 핵심: CVSS·EPSS·CISA KEV·ICS 권고·자산 맥락을 이용한 구성 위험점수와 실제 악용 가능성 예측을 분리한다.[^13]
- 데이터: 2020~2025년 CPPS/ICS 취약점 4,030건, 그중 CISA KEV 18건(0.45%)
- 확인 수치: 시간순 테스트 806건 중 양성 46건에서 exploit classifier의 RF PR-AUC는 0.378(95% CI 0.285~0.546), XGBoost Brier score는 0.0460이었다.[^13]
- 적용: 이상도와 실제 공격 가능성을 분리하는 설계 근거
- 한계: 높은 위험점수 회귀 R²는 저자가 만든 점수 공식을 잘 재현한 결과이지 실제 사고 위험을 맞힌 증거가 아니다.

### 2.8 Quantifying cyber threat using Bayesian statistical analysis

- 상태·발행일: **동료평가, 2026년 2월 5일**
- 핵심: 조직의 손실·시스템 위험·MITRE ATT&CK·공격 벡터를 연결하고 최근 90일 위협정보로 Bayes 사후확률을 갱신한다.[^14]
- 적용: 동일한 내부 이상도라도 최신 공격 증거가 있는 IP·전술의 위험도를 높이는 외부 보정 신호
- 한계: 실제 SOC 탐지모델 성능 실험이 아니라 예시와 PoC 중심이며, 전문가의 수작업 매핑과 강한 확률 가정에 의존한다.

### 2.9 On detection latencies of network intrusion detectors—discussion and application

- 상태·발행일: **동료평가, 2025년 11월 29일**
- 핵심: FPR뿐 아니라 공격 시작 후 최초 올바른 경보까지의 탐지 지연과 시퀀스 탐지율을 함께 측정한다.[^15]
- 데이터: 철도 임베디드, IIoT 엣지, 산업 IoT 네트워크의 산업 사례 3종
- 확인 수치: FPR 0.01 조건에서 평균 탐지 지연은 ROSPaCe에서 LSTMCD 5.57초·XGBoost 6.8초, Arancino에서 XGBoost 0.51초·LSTMCD 1.24초였다.[^15]
- 차이의 이유: 데이터셋·공격 종류·모델에 따라 최적 탐지기가 달라 단일 모델이 항상 빠르지 않았다.
- 한계: 많은 공개 데이터가 정상→공격 순서를 보존하지 않아 지연시간 평가에 부적합하다.

### 2.10 Multiclass Flow-Based Network Anomaly Detection under Severe Class Imbalance

- 상태·발행일: **동료평가, 2026년 9월 9일**
- 핵심: 심한 클래스 불균형에서 accuracy와 weighted-F1이 희귀 공격 탐지 실패를 숨기는지 비교한다.[^8]
- 데이터: CSE-CIC-IDS2018, 7개 클래스, 보류 테스트 2,434,942 flows
- 확인 수치: Random Forest macro-F1 0.7841·weighted-F1 0.9815, LightGBM macro-F1 0.7683·weighted-F1 0.9825였다.[^8]
- 적용: 프로젝트 평가표에 macro 및 공격 종류별 지표를 반드시 포함할 근거
- 한계: 단일 데이터셋의 무작위 분할이라 관련 흐름이 학습·시험에 함께 섞였을 가능성이 있고 외부 검증이 없다.

### 2.11 PACT: Reducing Alert Fatigue in Low-Prevalence SOC Streams with Triggered Active Learning

- 상태·발행일: **ACSAC 2026 제출 표기의 arXiv 사전공개, 2026년 5월 21일**
- 핵심: 낮은 공격 비율에서 F1만 보는 대신 정상 로그당 오탐 부담과 분석가 질의 수를 함께 평가한다.[^16]
- 데이터: AIT-ADS와 BOTSv1 공개 SOC 스트림
- 확인 수치: 고정 기준선 대비 오탐 부담을 각각 43%·21% 줄이고, 주기적 무작위 갱신보다 분석가 질의를 3.8배·5.2배 적게 사용했다.[^16]
- 반박 수치: 자유 실행 조건에서는 positive-window recall이 약 10%p 감소했고, 오탐만 최소화한 임계값 방식은 BOTSv1 recall이 55%p 무너졌다.[^16]
- 적용: `하루 경보 처리 한도 + 최소 재현율`을 동시에 운영 목표로 설정

### 2.12 Can Risk-Based Alerting Mitigate Cybersecurity Alert Fatigue?

- 상태·발행일: **USENIX Security '27 제출 표기의 arXiv 사전공개, 2026년 9월 2일**
- 핵심: 위험 기반 경보를 경보 발생 여부가 아니라 SOC 용량에 따른 연속 순위 문제로 평가한다.[^4]
- 데이터: 경보 데이터셋 8종, 그중 6종은 저자들이 생성 또는 확장
- 확인 수치: 조합형 RBA의 AUROC 평균 0.92·표준편차 0.09, 기존 severity 정렬은 평균 0.72·표준편차 0.21이었다.[^4]
- 적용: 위험점수의 1차 목적을 자동 차단보다 조사 순위화로 설정
- 한계: AUROC는 전체 순위 구분 능력이며 실제 Precision@K, 하루 오탐 수 또는 피해 감소를 직접 보장하지 않는다.

### 2.13 Adaptive Incident Prioritization for Security Operations at Scale

- 상태·발행일: **Microsoft 연구진의 arXiv 사전공개, 2026년 7월 18일**
- 핵심: 정규화된 보안 구성요소의 빈도·희귀도·도메인 지식으로 사건 큐를 계속 재정렬하고 구성요소별 설명을 제공한다.[^9]
- 확인 수치: 1,000개 고객 조직 전문가 평가에서 Precision@10 92.8%, 중간 추론 지연 5초; 공개 확장은 499개 조직 큐와 사건 9,980건이다.[^9]
- 운영 수치: 473,000개 조직-일 큐에서 severity 정렬 대비 상세 경보 상호작용 5.8%, 상세 보기 이벤트 17.5% 증가.[^9]
- 한계: 기업 연구진의 사전공개 결과이며 상호작용 증가는 정탐·피해 감소의 직접 지표가 아니다.

## 3. 수치를 직접 비교하면 안 되는 이유

논문마다 분석 대상과 분모가 다르다. 예를 들어 HSMLog는 HSM의 주입형 이상 시나리오를 평가했고, DDoS 연구는 SDN 네트워크 공격을 평가했으며, 불균형 연구는 243만여 flow의 7종 분류를 평가했다. 이들의 F1·TPR·FPR을 한 표에서 우열 순위로 만들면 잘못된 비교가 된다.

| 차이를 만드는 조건 | 비교 시 확인할 내용 |
|---|---|
| 분석 단위 | 로그 한 줄, 세션, flow, 사용자, 사건 중 무엇인가 |
| 공격 비율 | 전체 데이터 중 공격이 몇 %인가 |
| 데이터 출처 | 실제 사고, 실험실 공격, 합성·주입 공격 중 무엇인가 |
| 분할 방식 | 무작위, 시간순, 사용자 분리, 외부 데이터 검증 여부 |
| 임계값 | 최고 F1, 고정 0.5, 허용 오탐, Precision 하한 중 무엇인가 |
| 평가 목적 | 탐지, 확률 보정, 순위화, 자동 대응 중 무엇인가 |

## 4. 반박 의견과 객관성 검토

### 반박 1: 이상도가 높으면 공격인가?

아니다. 출장, 야간 배포, 백업, 장비 교체도 높은 이상도를 만들 수 있다. 이상도는 **조사 후보**를 찾는 값이며, 공격 확정에는 후속 행동·위협정보·자산 맥락이 필요하다.

### 반박 2: 여러 점수를 더하면 더 정확한가?

항상 그렇지 않다. 로그인 실패와 인증 실패율처럼 서로 겹치는 신호를 독립 증거처럼 더하면 위험을 중복 계산할 수 있다. 신호 제거 실험, 상관관계 점검, 가중치 민감도 분석이 필요하다.

### 반박 3: 오탐이 줄면 성능이 좋아진 것인가?

미탐이 함께 증가할 수 있다. PACT에서는 오탐을 더 낮춘 임계값 방식이 BOTSv1 재현율을 55%p 떨어뜨렸고, HSMLog의 정책 단독 방식은 정밀도 100%지만 재현율 21%였다.[^10][^16]

### 반박 4: 정확도 95%면 좋은 모델인가?

공격이 1%인 데이터에서는 모두 정상이라고 해도 정확도 99%가 된다. 최신 불균형 연구에서도 weighted-F1 약 0.98과 희귀 공격 F1 0.21이 동시에 나타났다.[^8]

### 반박 5: 위험점수의 80점은 공격 확률 80%인가?

아니다. 가중합 점수 80점은 팀이 만든 규칙의 결과일 수 있다. 공격 확률로 해석하려면 시간순 검증 데이터에서 calibration을 수행하고 Brier score·ECE·reliability curve로 확인해야 한다.[^7][^12]

### 반박 6: 공개 벤치마크 성능을 기업 로그에 적용할 수 있는가?

직접 적용할 수 없다. 로그 스키마, 공격 비율, 사용자 행동, 수집 누락과 업무 환경이 다르다. 같은 모델도 UNSW-NB15와 NSL-KDD에서 macro-F1과 Brier score가 크게 달랐다.[^12]

## 5. 테이렌 PoC 권장 설계

### 5.1 점수 구조

```text
행동 이상도 A
  ├─ Z-score 또는 Robust Z-score
  ├─ 신규 IP·자산 여부
  ├─ 시퀀스 이상도
  └─ 관계·분포 변화

공격 가능성 P
  ├─ 알려진 공격 규칙
  ├─ 위협정보 일치
  └─ 후속 행동 연결

업무 영향 C
  ├─ 사용자 권한
  ├─ 자산 중요도
  └─ 데이터 민감도

신뢰도 Q
  ├─ 기준선 데이터 양
  ├─ 결측·파서 오류
  └─ 보정된 모델 확률

최종 우선순위 R = f(A, P, C, Q)
```

초기 PoC는 설명 가능한 가중합을 사용할 수 있지만, `가중치 합=100%`라는 사실만으로 타당성이 생기지는 않는다. 가중치를 하나씩 제거하는 ablation과 ±10~20% 변경하는 민감도 분석으로 순위가 얼마나 흔들리는지 확인해야 한다.

### 5.2 위험 단계

임의의 `0~29 정상, 30~59 주의, 60~79 위험, 80~100 심각` 구간은 화면 예시로는 사용할 수 있지만 연구에서 공통으로 합의된 표준이 아니다. 실제 단계는 다음 운영 조건으로 결정하는 것이 더 객관적이다.

| 단계 | 결정 기준 예시 | 권장 대응 |
|---|---|---|
| 관찰 | 이상 신호가 있으나 공격 근거가 약함 | 기록 및 기준선 갱신 후보 |
| 확인 | 상위 K개 안에 들거나 복수 신호 발생 | 추가 로그 조회 |
| 조사 | 검증 데이터에서 정한 Precision 하한 충족 | 분석가 사건 조사 |
| 긴급 | 중요 자산·강한 공격증거·높은 신뢰도 | 승인 후 세션 제한·격리 검토 |

### 5.3 최소 평가표

| 평가 항목 | 필수 지표 |
|---|---|
| 탐지 품질 | 클래스별 Precision·Recall·F1, macro-F1, PR-AUC |
| 오탐 부담 | FPR, 하루 오탐 건수, 사용자 1,000명당 오탐 수 |
| 사건 탐지 | 사건·시퀀스 단위 Recall, 중복 경보 수 |
| 속도 | 최초 탐지 지연, 집계·추론 처리시간 |
| 확률 신뢰성 | Brier score, ECE, 오답 신뢰도 |
| 분석가 효율 | Precision@K, 하루 검토 가능 K, 평균 조사시간 |
| 안정성 | 기간·사용자·공격종류별 성능, 데이터 드리프트 |

### 5.4 검증 방법

1. 과거 기간을 학습, 그다음 기간을 검증, 가장 최근 기간을 테스트로 사용한다.
2. 같은 사용자의 거의 동일한 로그가 학습·시험에 섞이지 않도록 사용자·세션 그룹 분리를 추가한다.
3. 정상·단일 이상·복합 이상·희귀 공격을 별도로 평가한다.
4. 임계값은 최고 정확도가 아니라 최소 재현율과 하루 처리 가능한 경보 수를 함께 만족하도록 선택한다.
5. 배포 초기에는 Shadow Mode로 운영하고 자동 차단 없이 분석가 판정을 수집한다.
6. `unknown` 판정을 정상 라벨로 강제 변환하지 않는다.

## 6. 최종 합의안

네 전문 관점에서 가장 일관되게 남는 결론은 다음과 같다.

> **사용자·자산별 기준선에서 여러 종류의 이상도를 계산하되, 이상도 자체를 공격 확률로 부르지 않는다. 반복·시퀀스·위협정보·자산 중요도를 결합하고 확률과 불확실성을 검증한 뒤, 설명 가능한 위험 순위로 제공한다. 운영 평가는 정확도보다 희귀 공격 재현율, 오탐의 절대 건수, 탐지 지연과 분석가 처리 한도를 함께 본다.**

확인된 사실은 최근 논문들이 단일 이상점수와 accuracy 중심 평가의 한계를 반복해서 보여준다는 점이다. 분석적 권고는 테이렌 PoC에서 먼저 설명 가능한 단순 모델을 구현하고, 실제 로그와 분석가 판정이 쌓인 뒤 확률 보정·동적 가중치·시퀀스 모델을 단계적으로 추가하는 것이다.
