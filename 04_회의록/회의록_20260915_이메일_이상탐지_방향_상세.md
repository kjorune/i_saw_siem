# 프로젝트 상세 회의록

- 회의명: 이메일 기반 사용자 행동 이상탐지 주제 및 기획안 검토 회의
- 일시: 2026.09.15
- 참석자: 이소이, 권순성, 김솔, 김현수, 강사님
- 회의 목표: 샘플 데이터 분석 결과를 공유하고 프로젝트 주제, 위험지표, 검증방법 및 기획안 작성 방향 확정

## 1. 주요내용

팀은 오전 11시까지 샘플 데이터와 전일 회의 내용을 개별 검토한 뒤 분석 방향을 논의했다. 슬랙을 통해 SIME 조기탐지 MVP 개발기획서, NIA 이메일 유출 사례, 사용자 행동 이상탐지 가기획안, 샘플 데이터 정의서, 이메일 Z-score 결과와 위험지표 근거자료를 공유했다.

초기에는 로그인·파일·USB·이메일·웹 로그를 결합한 다중 로그 조기탐지를 검토했다. 그러나 실제 개발기간이 약 7일이고 일부 로그의 컬럼이 제한적이어서 이메일 기반 외부 자료반출 이상징후 탐지를 핵심 주제로 좁히고, 파일 활동은 주요 선행 정황, USB·로그온·웹 로그는 보조 또는 향후 확장 범위로 관리하기로 했다.

분석은 LDAP에 등록된 직원 이메일과 `email.from`이 일치하는 이벤트를 발신 후보로 선별하고 회사 외부 수신자가 포함된 메일을 대상으로 수행한다. 사용자별 하루 단위로 외부메일 수, 외부 수신자 수, 첨부파일 수, 이메일 크기, 활동 시간, 신규 대상과 반복 전송 지표를 생성하고 과거 최대 30일 행동과 비교한다.

공유된 분석 결과에서는 원본 이메일 1,314,400건 중 월별 LDAP와 발신자가 일치한 815,250건을 분석 후보로 제시했다. 이 가운데 외부 수신자가 포함된 이벤트는 136,519건, 사용자×일 기록은 289,783건이었으며, 파일 활동 급증 후 2시간 이내 외부 첨부메일과 크기 증가 또는 복수 첨부가 이어진 후보 95건·51개 계정이 제시됐다.

위 수치는 구현 가능성을 확인하기 위한 분석 근거이며 실제 정보유출 정답을 의미하지 않는다. 공격 라벨이 없으므로 정상·단일 이상·복합 이상 시나리오로 점수 상승과 탐지 여부를 검증하고, 결과는 실제 유출자가 아닌 조사 우선 후보로 표현한다.

강사님은 데이터 근거와 주제는 적절하지만 기획서가 길고 분석 과정과 결론의 연결이 직관적이지 않다고 피드백했다. 본문은 1~2장으로 축약하고 프로젝트 목적에서 분석 근거·방법·예상 결과·수행계획으로 이어지는 흐름을 명확히 하며, 상세 통계·코드·복잡한 점수식과 부가 그래프는 부록으로 분리하기로 했다.

## 2. 논의

### 안건 1. 자료 검토와 업무 진행

- 오전 10시에 팀원별로 샘플 데이터와 전일 회의 내용을 검토하고 오전 11시에 모여 논의하기로 했다.
- 현재는 샘플 데이터이지만 실제 기업 데이터가 제공됐을 때 다시 기획하지 않도록 전환 가능성을 고려하기로 했다.
- 이소이는 SIME 조기탐지 MVP 기획서와 이메일 중심 분석·위험지표 자료를 공유했다.
- 김현수는 NIA 사례 연계안, 데이터 정의서, 이메일 분석 자료와 기획안 수정본을 공유했다.
- 김솔은 로그인·파일·USB 중심 사용자 행동 이상탐지 가기획안과 프로젝트 개요·추진 배경을 정리했다.
- 권순성은 데이터 정제 기준, PPT 작성 자료와 PDF 재제출 업무를 정리했다.

### 안건 2. 데이터 구조와 정규화

- 샘플은 `email`, `file`, `device`, `logon`, `http`, LDAP 및 사용자 특성 데이터로 구성된다.
- 활동 로그는 사용자·시간·PC로 연결할 수 있고 활동 사용자는 LDAP 사용자와 매칭 가능한 것으로 공유됐다.
- 데이터 정의서에서는 7개 파일 4,445,120개 행의 구조·기간·결측·중복·연결 관계를 검토했다고 보고했다.
- 이벤트 ID 중복과 날짜·숫자 파싱 실패는 확인되지 않았고, 이메일의 `cc`, `bcc`와 LDAP 일부 조직 컬럼에는 빈 값이 존재했다.
- 사용자 컬럼명은 `user_id`에서 `user`로 통일하고 날짜는 ISO 8601 형식으로 변환하기로 했다.
- LDAP는 월별 스냅샷이므로 이메일 발생 월과 같은 월의 LDAP를 우선 연결하고 대체 규칙을 명시해야 한다.
- `email.size`의 단위와 첨부 포함 여부, 파일 작업 종류·크기·복사 방향은 확인이 필요하다.

### 안건 3. 프로젝트 주제와 범위

- USB 반출, 이메일 외부 유출, 웹 업로드, 계정·PC 오용 등을 후보로 검토했다.
- 이메일 로그는 발신·수신자, 크기, 첨부, BCC 및 시간 정보가 있어 다양한 행동지표를 만들 수 있다고 판단했다.
- NIA 사례처럼 외부 이메일 전송이 장기간 반복될 수 있다는 점을 주제 선정 근거로 활용한다.
- 최종 주제는 `SIEM 로그 기반 이메일 외부 유출 위험 사용자 탐지 및 위험 스코어링`으로 정리했다.
- 실제 유출자를 확정하지 않고 평소 행동에서 벗어난 외부 전송을 찾아 조사 우선순위를 제공한다.
- 실시간 수집·자동 차단·상용 SIEM 연동은 제외하고 샘플 기반 MVP와 실제 데이터 전환 구조에 집중한다.

### 안건 4. 이메일 발신 후보와 분석 단위

- `email`에는 발송·수신을 나타내는 `activity`가 없어 외부 주소 포함 이벤트를 모두 발신으로 해석하지 않는다.
- 이메일 발생 월의 LDAP에서 `user`와 등록 이메일을 연결하고 `email.from`이 등록 이메일과 일치하는 경우만 발신 후보로 사용한다.
- `to`, `cc`, `bcc` 중 회사 도메인 외 주소가 하나 이상 존재하면 외부 발송 후보로 분류한다.
- 기본 분석 단위는 사용자×일이며 이벤트 원본은 근거 확인용으로 유지한다.
- 외부메일 수, 외부 수신자, 신규 수신자·도메인, 첨부 수, 메일 크기, BCC, 비근무시간과 반복 전송을 Feature로 검토한다.
- 유형별 이벤트 수뿐 아니라 사용자 수와 유형 간 중복도 함께 집계한다.

### 안건 5. 개인 기준선과 위험지표

- 모든 사용자에게 같은 절대기준을 적용하지 않고 현재 날짜 이전 최대 30일 기록을 개인 기준선으로 사용한다.
- 미래정보 누수를 막기 위해 현재 이후 기록은 기준선에 포함하지 않는다.
- 외부메일·첨부·메시지 크기·수신자 수에 대해 Z-score 결과를 먼저 탐색했다.
- 치우친 분포와 극단값의 영향을 줄이기 위해 중앙값과 MAD 또는 IQR을 사용하는 Robust Z-score를 우선 검토한다.
- 임계값은 임의의 절대값이 아니라 데이터 분포, 논문과 멘토·실무자 의견을 결합해 결정한다.
- 위험지표 정의·임계값·설정 근거는 한 표에서 함께 제시한다.

### 안건 6. 파일·USB와 다중 로그 활용

- 파일 로그는 이메일 발신 전 파일 활동량 증가를 확인하는 선행 정황으로 사용한다.
- 주요 복합 후보는 `파일 활동 급증 → 2시간 이내 외부 첨부메일 → 평소보다 큰 메일 또는 첨부 2개 이상`으로 제안됐다.
- 시간적 근접성은 연관성의 근거이며 실제 파일 첨부나 유출의 인과관계를 증명하지 않는다.
- USB 로그는 장치 ID·종류·전송량이 없어 독립적인 자료반출 판정이 어렵다.
- USB는 이메일 활동 전후 같은 사용자·PC에서 발생한 보조 정황으로 제한하거나 향후 확장 범위로 둔다.
- 로그온과 웹도 현재 MVP의 필수 입력보다 후속 시퀀스 분석 후보로 관리한다.

### 안건 7. 모델과 위험점수

- 위험점수는 외부메일·첨부·크기·신규 대상·반복성과 같은 설명 가능한 행동지표를 중심으로 구성한다.
- 규칙 기반 점수와 Robust Z-score를 기본 방식으로 사용하고 Isolation Forest는 선택적 비교 모델로 검토한다.
- Isolation Forest에는 사용자 식별값이 아닌 개인 기준선 대비 편차 Feature를 입력한다.
- 모델 점수를 실제 공격 확률로 해석하지 않고 같은 신호를 규칙과 모델에서 중복 가산하지 않도록 한다.
- 논문은 지표와 방법의 근거로 사용하며 정확한 가중치의 표준으로 해석하지 않는다.
- 초기 가중치는 MVP용 값으로 두고 실제 데이터와 실무자 피드백으로 재조정한다.

### 안건 8. 라벨과 검증방법

- 샘플 파일에는 실제 악성 여부를 나타내는 명시적인 정답 컬럼이 없다.
- 이메일 이벤트 유형은 조사 후보를 만들기 위한 약한 라벨이며 실제 해킹·유출의 정답이 아니다.
- 정상, 단일 이상, 복합 이상 시나리오를 구성해 점수가 단계적으로 상승하는지 확인한다.
- 검증표는 추상적인 행동 예시보다 실제로 달라지는 Feature를 표시한다.
- 규칙 기반, Isolation Forest 단독 및 결합 방식은 탐지시점·점수 차이·상위 경보 진입과 경보량으로 비교한다.
- Sigma Rule은 규칙 구조를 참고할 수 있지만 현재 샘플과 대상 로그가 달라 공개 규칙을 직접 적용하기 어렵다고 판단했다.

### 안건 9. 강사 피드백과 기획서 재구성

- 프로젝트 주제와 데이터 근거는 적절하다는 평가를 받았다.
- 기존 기획서는 길고 분석 단계가 나온 이유와 결론의 연결이 약하다는 피드백을 받았다.
- 본문은 1~2장으로 줄이고 `무엇을 할 것인가 → 왜 필요한가 → 데이터에서 가능한가 → 어떻게 구현할 것인가 → 무엇이 나오는가 → 누가 언제 수행하는가` 흐름으로 구성한다.
- 상세 분석, 코드, 점수 분포, 복잡한 신뢰도 계산과 부가 그래프는 부록으로 옮긴다.
- 본문에는 프로젝트 개요, 추진 배경, 데이터 분석 근거, 개발계획, 예상 결과물, 역할과 일정만 남긴다.
- 위험지표 정의·계산식·임계값 근거는 간결한 표 하나로 제시한다.
- 설명하기 어려운 용어와 과도한 영문 표현을 제거하고 문장을 짧고 직접적으로 수정한다.
- 실제 라벨이 없는 상태에서는 X·Y보다 입력 행동지표와 출력 위험점수를 중심으로 설명한다.

### 안건 10. 업무 분담과 제출

- 이소이는 분석자료와 팀원 초안을 결합해 통합 기획서를 작성하고 개발계획·역할 부록을 정리했다.
- 김현수는 NIA 사례, 이메일 발신 후보 정의, 데이터 정의서와 기획안 수정본을 작성했다.
- 김솔은 프로젝트 개요·추진 배경과 사용자 행동 이상탐지 구조를 정리했다.
- 권순성은 사용자·날짜 컬럼을 정제하고 PPT 작성 프롬프트와 양식을 준비했다.
- 팀원별 목차를 비교해 프로젝트 개요, 추진 배경, 데이터 분석 근거, 개발계획, 결과물, 역할과 일정 순으로 통합했다.
- 권순성은 강사 피드백을 반영한 김현수·이소이 작성 자료를 PDF로 변환해 다시 제출하기로 했다.

| 기획서 본문은 1~2장으로 축약 | 핵심 흐름을 직관적으로 보여달라는 강사 피드백 반영 | 피드백 요약, 목차 제안 |
| 상세 분석은 부록으로 분리 | 가독성을 높이면서 분석 근거와 재현성을 유지하기 위함 | 데이터 정의서, 위험지표 상세서 |
