# 1. 프로젝트 개요

## 프로젝트명

**SIEM 로그 기반 이메일 외부 유출 위험 사용자 탐지 및 위험 스코어링**

## 목표 및 범위

본 프로젝트는 이메일 로그와 직원 계정 정보(LDAP)를 활용해 사용자의 평소 행동에서 벗어난 외부 전송을 탐지하고, 위험점수와 조사 우선순위를 제공한다.

| 구분 | 내용 |
|---|---|
| 목표 | 외부 전송 이상징후를 탐지해 조사 대상의 우선순위를 제시한다. |
| 분석 데이터 | 직원 계정 정보(LDAP), 장치, 이메일, 파일, 웹, 로그온, 성격 특성 데이터 |
| 분석 단위 | 사용자별 하루(User×Day) 이메일 활동 |
| 분석 방법 | 사용자의 평소 행동과 현재 행동의 차이를 계산하고 복합 이상행동을 탐지한다. |
| 결과물 | 위험 사용자 순위, 위험점수, 위험등급, 점수 산정 근거 |
| 해석 범위 | 실제 정보유출자를 확정하지 않고 조사가 필요한 사용자를 선별한다. |
| 확장 범위 | 장치·파일·웹·로그온 활동을 결합한 다중 로그 분석으로 확장한다. |

# 2. 추진 배경

## 실제 정보유출 사례

NIA 사례에서는 한 직원이 2022년부터 약 3년간 기관 이메일로 외부 업체 관계자에게 비공개 자료를 380회 전달한 것으로 알려졌다. 반복적인 외부 전송이 장기간 탐지되지 않았다는 점에서 사용자별 이메일 행동을 지속적으로 분석할 필요성을 확인했다.

본 프로젝트는 이러한 사례를 참고해 장기간 반복되는 외부 이메일 전송, 새로운 외부 수신자, 첨부파일 증가, 평소보다 큰 메시지 및 비정상 시간대 활동을 탐지 대상으로 설정한다.

다만 제공된 로그만으로 실제 자료의 기밀성, 전달 성공 여부 또는 사용자의 악의성을 확인할 수 없다. 따라서 분석 결과는 정보유출 확정이 아니라 조사 대상의 우선순위를 정하는 근거로 활용한다.

## 주제 선정 이유

- 평소와 다른 수신자, 전송량, 첨부파일 사용과 반복 전송을 분석해 정보유출 징후를 조기에 탐지할 수 있다.
- 제공된 이메일 로그에는 사용자, PC, 발신·수신 주소, 시간, 메시지 크기, 첨부파일 및 BCC 정보가 포함돼 있다.
- 이메일 활동 전후의 파일 로그를 연결하면 단일 이메일만으로 확인하기 어려운 복합 행동을 탐지할 수 있다.
- 위험점수와 점수 산정 근거를 함께 제공하면 보안 담당자가 조사 대상을 효과적으로 선별할 수 있다.

# 3. 데이터 분석 근거

본 프로젝트는 이메일·직원 계정 정보·파일 로그를 결합해 사용자의 평소 행동에서 벗어난 외부 전송과 그 선행 행동을 탐지하고, 조사 우선순위를 제시한다.

## 제공 로그와 핵심 데이터

| 데이터 | 핵심 항목 | 활용 목적 |
|---|---|---|
| 이메일 | 시간, 사용자, PC, 발신·수신 주소, 메시지 크기, 첨부 수 | 외부 수신자, 첨부, 전송 규모, 시간대 및 신규 목적지 분석 |
| 직원 계정 정보(LDAP) | 사용자 ID, 회사 이메일, 직무, 조직 | 이메일 발신자 확인, 회사 내부·외부 주소 구분 |
| 파일 | 시간, 사용자, PC, 파일명 | 외부메일 발생 전 파일 활동 급증 탐지 |
| 장치 | 시간, 사용자, PC, 연결·해제 활동 | 이동식 장치 사용과 파일·메일 활동의 연관성 검토 |
| 로그온 | 시간, 사용자, PC, 로그인·로그오프 | 사용자 세션 및 평소와 다른 활동시간 검토 |
| 웹 | 시간, 사용자, PC, URL | 새로운 외부 도메인 및 웹 활동 변화 검토 |
| 성격 특성 | 사용자 ID, OCEAN 점수 | 행동 분석의 보조 속성으로만 검토 |

각 로그의 컬럼, 데이터 형식, 연결 방법과 해석 시 주의사항은 부록 A의 제공 로그 데이터 상세 정의를 참고한다.

## 데이터 정제 기준

| 정제 항목 | 적용 기준 |
|---|---|
| 사용자 컬럼명 | 활동 로그의 사용자 식별 컬럼을 `user`로 통일 |
| 날짜·시간 형식 | 날짜를 `YYYY-MM-DDTHH:MM:SS` 형식으로 통일 |
| 이메일 주소 | 앞뒤 공백을 제거하고 영문 대소문자를 통일 |
| 복수 수신자 | `to`, `cc`, `bcc`를 세미콜론 기준으로 분리 |
| 내부 도메인 | 주소 도메인이 정확히 `dtaa.com`일 때 내부로 분류 |
| 발신자 확인 | 이메일 로그의 `user`와 `from`이 해당 월 LDAP의 사용자 및 회사 이메일과 모두 일치하는지 확인 |
| 분석 단위 | 이벤트를 사용자별 하루(User×Day) 단위로 집계 |

## 분석 모집단

원본 이메일 1,314,400건 중 이메일 기록의 `user`와 발신 주소가 당시 직원 계정 정보의 사용자 및 회사 이메일과 모두 일치한 815,250건을 분석 대상으로 사용한다.

이 가운데 외부 수신자가 포함된 이벤트는 136,519건으로, 발신 검증 이벤트의 16.75%다. 분석 대상 고유 계정은 1,000개이며, 사용자별 하루 분석 레코드는 289,783건이다.

> **외부 발송 후보 = 이메일 기록의 사용자·발신 주소가 직원 계정 정보와 일치하고 회사 외부 수신자가 1명 이상 존재하는 이벤트**

외부 주소가 포함됐다는 사실만으로 정보유출이나 악성 행위를 확정하지 않는다.

## 개인별 평소 행동과 비교

사용자마다 담당 업무와 평소 이메일 사용량이 다르므로 모든 사용자에게 동일한 절대 기준을 적용하지 않는다. 각 사용자의 현재 날짜 이전 최대 30개 관찰일을 기준선으로 설정하고 현재 행동과 비교한다. Robust Z-score가 클수록 현재 행동이 해당 사용자의 평소 행동보다 크게 증가했다는 의미다. 현재 날짜 이후의 기록은 과거 기준선에 포함하지 않는다.

## 주요 분석지표

| 분석지표 | 계산·판단 기준 | 분석 목적 |
|---|---|---|
| 외부메일 수 | 외부 수신자가 포함된 이메일 수 | 외부 전송 활동량 확인 |
| 외부 수신자 수 | `to`, `cc`, `bcc`의 외부 주소 수 | 전달 범위 확인 |
| 외부 도메인 수 | 외부 주소의 고유 도메인 수 | 전달 대상 다양성 확인 |
| 신규 외부 수신자 | 해당 사용자에게 과거에 없었던 외부 주소 | 새로운 전달 경로 탐지 |
| 신규 외부 도메인 | 해당 사용자에게 과거에 없었던 외부 도메인 | 새로운 조직·서비스 탐지 |
| 외부 첨부메일 | 외부 수신자와 첨부파일이 함께 존재하는 이메일 | 자료 전달 가능성 확인 |
| 메시지 크기 변화 | 사용자 과거 기준 대비 메시지 크기 증가 | 평소보다 큰 자료 전송 탐지 |
| 외부 BCC | 외부 주소가 BCC에 포함된 이메일 | 수신자 비공개 전송 확인 |
| 비정상 시간대 | 주말 또는 평일 08시 이전·19시 이후 | 근무시간 외 활동 탐지 |
| 파일 활동 급증 | 과거 기준 대비 파일 이벤트 증가 | 이메일 전 자료 취급 증가 탐지 |
| 반복 외부 전송 | 동일 주 또는 여러 주에 걸친 외부 활동 | 장기·반복 전송 탐지 |

## 분석 결과의 개발 적용

| 분석 결과 | 확인 내용 | 개발 적용 |
|---|---|---|
| 과거 기록 확보 | 전체 분석일 중 89.66%는 사용자별 과거 기록이 30일 이상 존재 | 개인 기준선 기반 비교 |
| 비정상 시간대 활동 | 6,761개의 사용자×일 기록에서 평소와 다른 시간대 활동 확인 | 개인의 평소 시간대와 비교 |
| 파일 활동 급증 | 과거 30일 대비 파일 활동 Robust Z-score가 3 이상인 날 3,907건 | 이메일 전 파일 활동을 선행 신호로 활용 |
| 파일-메일 복합행동 | 파일 급증 후 외부 첨부메일과 크기 증가 또는 복수 첨부가 이어진 후보 95건·51개 계정 | 우선 조사 대상 선정 |
| 외부 첨부·크기 증가 | 첨부 수, 메시지 크기와 수신자 수가 함께 증가한 날짜 확인 | 자료량과 전달 범위가 증가한 사례 탐지 |
| 장기 반복 활동 | 여러 주에 걸쳐 외부 이메일을 반복한 사용자 확인 | NIA 사례와 유사한 장기 반복 행동 탐지 |

## 데이터 제약사항

| 제약 | 대응 원칙 |
|---|---|
| 이메일에 발송·수신 구분 항목이 없음 | `user`와 `from`이 LDAP의 사용자·회사 이메일과 일치하는 경우만 발신 후보로 사용 |
| 메시지 크기의 단위와 첨부 포함 여부가 불명확 | 절대 전송량이 아니라 사용자 과거 행동 대비 변화로 해석 |
| 파일 로그에 작업 종류·크기·복사 방향이 없음 | 파일 활동과 이메일의 시간적 선후관계만 제시 |
| 근무표·승인 외부 도메인 정보가 없음 | 비근무시간과 신규 목적지는 보조 지표로 사용 |
| 실제 유출 여부를 나타내는 정답 데이터가 없음 | 정확도를 주장하지 않고 탐지 근거와 조사 우선순위를 제시 |
| 파일 해시와 메일 첨부파일 정보가 없음 | 파일 이벤트와 첨부파일의 동일성을 확정하지 않음 |
| 로그 시간대 정보가 없음 | 특정 국가·지역의 시간대로 임의 해석하지 않음 |

# 4. 개발 계획

핵심 개발 방향은 개인의 평소 행동과 현재 행동을 비교하고 여러 로그의 발생 순서를 연결해, 이해하기 쉬운 위험점수와 조사 근거를 제공하는 것이다.

## 전체 분석 흐름

분석의 핵심 지표는 ① 평소와 다른 시간대의 활동, ② 외부메일 발송 급증, ③ 외부 첨부·메시지 크기·수신자 증가, ④ 파일 활동 급증이다. 특히 **파일 활동 급증 → 2시간 이내 외부 첨부메일 → 평소보다 큰 메일 또는 첨부 2개 이상**의 흐름을 주요 위험행동 후보로 탐지한다.

## 기술 스택

| 구분 | 기술 | 용도 |
|---|---|---|
| 데이터 저장·조회 | SQLite, CSV | 로그 조회 및 중간 분석 결과 관리 |
| 데이터 처리·분석 | Python, Pandas, NumPy | 주소 파싱, 데이터 연결, 사용자×일 집계 |
| 통계 기반 탐지 | 개인 기준선, Robust Z-score | 평소보다 크게 증가한 행동 탐지 |
| 조건 기반 탐지 | Rule, Novelty, Sequence | 신규 목적지, 반복 행동 및 파일-메일 순서 탐지 |
| 비교 모델 | Isolation Forest | 여러 행동이 동시에 달라진 사례의 추가 탐색 |
| 결과 제공 | Streamlit 또는 Jupyter | 위험 사용자 순위 및 사용자 상세 근거 제공 |
| 협업·문서화 | GitHub, Notion | 코드 버전 관리, 지표 정의 및 분석 기준 공유 |

# 5. 결과 제공 화면

분석 결과는 위험 사용자를 우선적으로 확인하고, 각 사용자의 위험점수 산정 근거를 추적할 수 있는 대시보드로 제공한다.

## 위험 사용자 순위

**위험점수 기반 조사 우선순위를 제공하는 사용자 Ranking 화면**

사용자×일 단위의 위험점수와 위험등급을 기준으로 조사 대상을 정렬한다. 외부메일, 외부 수신자, 신규 수신자, 첨부메일, 메시지 크기, 외부 BCC 및 비정상 시간대 활동 등 주요 지표를 함께 표시하여 사용자 간 위험 수준을 비교할 수 있도록 한다.
