# 프로젝트 운영 규칙

## 1. 소통 및 기록

| 목적 | 사용 도구 |
|---|---|
| 팀 내부 주 소통 | Slack |
| 멘토링·외부 연락 | 카카오톡 |
| 코드·기술 문서 | GitHub |
| 일반 문서·대용량 자료 | Google Drive |
| 일정·결정·진행 현황 | Notion |

- 중요한 결정은 메신저에만 남기지 않고 Notion 또는 GitHub 문서에 기록한다.
- 팀원은 당일 작성하거나 수정한 문서와 산출물을 Slack으로 공유한다.
- 권순성이 하루 동안 공유된 자료를 취합하여 GitHub에 반영한다.

## 2. 과업 관리

Notion 과업에는 다음 내용을 기록한다.

- 과업명과 작업 목적
- 작업 절차
- 담당자와 검토자
- 작업 기간과 우선순위
- 현재 상태와 진행률
- 세부 작업
- 완료 기준
- 관련 문서와 링크

작업 완료는 구현뿐 아니라 자체 검증, 리뷰, 피드백 반영과 산출물 등록까지 마친 상태를 의미한다.

## 3. 폴더 관리

기본 폴더는 다음과 같이 구분한다.

- `00_프로젝트관리`: 운영 규칙, 역할, 일정, 체크리스트
- `01_프로젝트기획`: 목표, 범위, 요구사항, WBS, 기획서
- `02_자료조사`: 사례, 논문, 기술 조사, 데이터 사전
- `03_데이터분석`: EDA, 분석 설계, 분석 보고서, 노트북
- `04_회의록`: 회의록과 회의 녹취
- `05_코드`: 재실행 가능한 코드
- `06_산출물`: 보고서, 발표자료, 분석 결과, 검증 결과
- `07_데이터`: 원본 및 가공 데이터

운영 기준은 다음과 같다.

- 폴더 깊이는 최대 3단계를 권장한다.
- 각 폴더 최상위에는 현재 사용 중인 최신 문서와 산출물만 둔다.
- 같은 문서의 이전 버전은 해당 폴더의 `이전버전/`에 보관한다.
- 같은 문서를 여러 위치에 복사하지 않는다.
- 표준 `이전버전/` 외에 `최종`, `진짜최종`, `구버전`, `백업` 폴더를 만들지 않는다.
- 원본 데이터와 가공 데이터를 분리한다.
- 실행 결과는 `06_산출물`에 저장한다.

## 4. 파일명 규칙

기본 형식은 다음과 같다.

```text
[문서번호_]주제_내용[_YYYYMMDD][_vNN][_상태].확장자
```

공식 상태명은 다음 네 가지만 사용한다.

- `작업본`
- `검토본`
- `현행본`
- `제출본`

예시는 다음과 같다.

```text
02_분석설계_20260921_v01_검토본.pdf
04_위험점수_산정기준_20260922_v02_현행본.pdf
07-1_최종발표자료_2팀_20260928_v01_제출본.pptx
```

`최종`, `진짜최종`, `최종수정`, `완성본`, `수정본`은 사용하지 않는다.

## 5. 버전관리

- 편집 가능한 작업 원본은 한 개만 유지한다.
- 일반 변경 이력은 Git 커밋으로 관리한다.
- 공식 검토·승인·제출 시점에만 `vNN` 파일을 만든다.
- 최초 공식 버전은 `v01`이다.
- 내용이 변경되면 `v02`, `v03` 순서로 증가시킨다.
- 같은 내용의 PPTX와 PDF는 동일한 버전을 사용한다.
- `현행본`은 문서별로 한 개만 유지한다.
- 최신 공식본은 해당 번호 폴더 최상위에 두고 이전 공식본은 `이전버전/`으로 이동한다.
- `제출본`은 수정하지 않고, 변경이 필요하면 새 버전으로 만든다.
- 공식 산출물은 `산출물_버전기록.md`에 작성자, 검토자, 변경 내용과 관련 커밋을 기록한다.

## 6. GitHub 협업

기본 흐름은 다음과 같다.

```text
팀원 작업
→ Slack으로 문서·산출물 공유
→ 권순성이 파일명·버전·보안 항목 확인
→ Issue 및 작업 브랜치 정리
→ Commit·Push
→ Pull Request 검토
→ main 반영
```

- 권순성이 일일 GitHub 반영과 버전관리를 담당한다.
- `main`에는 검토가 끝난 안정 버전만 유지한다.
- 브랜치 하나에는 한 가지 작업 목적만 담는다.
- 커밋 하나에도 한 가지 목적의 변경만 포함한다.
- 커밋 메시지는 `종류: 변경 내용` 형식을 사용한다.
- 개인정보, 비밀키와 대용량 원본 데이터는 커밋하지 않는다.
- Slack 공유만으로 완료된 것이 아니며, GitHub 반영까지 확인되어야 완료로 본다.
