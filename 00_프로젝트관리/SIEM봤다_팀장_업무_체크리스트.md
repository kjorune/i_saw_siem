# SIEM봤다! 팀장 업무 체크리스트

## 1. 외부 관계자와 소통

- [ ] 멘토·강사·매니저 일정 파악
- [ ] 질문과 요청 사항 취합
- [ ] 진행 상황과 주요 이슈 공유
- [ ] 피드백 내용 기록 및 팀 전달
- [ ] 데이터·자료 요청 현황 관리
- [ ] 회의 일정과 사전 준비물 공지
- [ ] 외부 전달 전 문서 내용과 팀 의견 확인

> 팀장이 모든 질문에 직접 답하기보다 질문을 취합하고 적절한 담당자가 답변하도록 연결한다.

| 목적 | 사용 도구 |
|---|---|

- [ ] 채널별로 어떤 정보를 기록할지 팀에 공유

- [ ] 공식 산출물의 버전 기록에 변경 내용과 관련 커밋·PR 추가

## 3. 프로젝트 목표와 범위 관리

- [ ] 최종 프로젝트 목표를 한 문장으로 확정
- [ ] 반드시 구현할 최소 기능 정의
- [ ] 시간이 남으면 구현할 선택 기능 분리
- [ ] 이번 프로젝트에서 하지 않을 기능 기록
- [ ] 최종 산출물 목록 확정
- [ ] 멘토 피드백으로 범위가 변경되면 변경 이유 기록
- [ ] 9월 29일까지 완료 가능한 범위인지 지속적으로 점검

| 구분 | 현재 후보 |
|---|---|
| 필수 | Email·LDAP 전처리 및 연결, 사용자별 정상 행동 기준선, 이상 탐지, 위험 점수, 사용자 순위·상세 화면 |
| 미정 | File·Device 로그 연계 |
| 선택 | Isolation Forest 비교 |
| 향후 확장 | 실시간 RCF, OpenSearch 연동, 대규모 서비스화 |

현재 팀은 권순성, 김솔, 김현수의 3인 체제로 운영한다. 이소이는 2026년 9월 17일부터 취업으로 팀에서 제외한다.

## 4. 업무 분배 및 WBS 관리

- [ ] 팀원의 경험·관심 분야·가능 시간 파악
- [ ] 업무별 주 담당자와 검토자 지정
- [ ] 업무별 완료 기준과 산출물 정의
- [ ] 업무 간 선후관계 확인
- [ ] 특정 팀원에게 업무가 집중되지 않는지 점검
- [ ] 매일 완료·진행·차질 사항 확인
- [ ] 지연 발생 시 일정 또는 범위 조정

업무는 `데이터 분석`과 같이 크게 배정하지 않고 결과물이 보이는 수준으로 분해한다.

```text
로그 분석
├─ 파일별 기간·행 수 정리
├─ 컬럼 설명서 작성
├─ 조인 키 확인
├─ 결측치·중복값 확인
└─ 사용자별 기초 통계 작성
```

## 5. 의사결정 관리

각 결정에 다음 내용을 기록한다.

- 무엇을 결정했는가
- 왜 그렇게 결정했는가
- 검토한 다른 대안은 무엇인가
- 아직 결정되지 않은 것은 무엇인가
- 언제 다시 판단할 것인가

### 결정 상태를 관리할 핵심 사항

- [ ] 핵심 위협 탐지 주제
- [ ] 분석 단위: 사용자·세션·사건
- [ ] 정상·이상 행동 기준
- [ ] 위험 점수 산식
- [ ] 라벨 데이터 구성 방법
- [ ] 사용할 분석 도구와 모델
- [ ] `content` 컬럼 사용 여부

- [ ] 개인정보·민감정보 포함 여부 확인
- [ ] 팀 외부 공유 가능 범위 확인
- [ ] 데이터 경로와 접근 권한 관리
- [ ] 분석에 사용한 데이터 버전 기록

## 7. 분석 품질 관리

- [ ] 지표와 가중치에 근거가 있는지 확인
- [ ] 팀원들이 정상·이상 기준을 동일하게 이해하는지 확인
- [ ] 같은 데이터에서 코드가 같은 결과를 내는지 검증
- [ ] 중간 결과에 오류나 데이터 누락이 없는지 점검
- [ ] Z-score와 비교 모델의 평가 기준 통일
- [ ] 라벨이 없다면 결과를 정확도라고 표현하지 않도록 주의
- [ ] 다른 팀원이 분석 결과를 재현할 수 있는지 확인

## 10. 팀장 일일 점검

1. 어제 완료한 것은 무엇인가?
2. 오늘 완료할 것은 무엇인가?
3. 현재 막힌 부분은 무엇인가?
4. 다른 팀원의 도움이 필요한가?
5. 일정이나 범위를 바꿔야 하는가?

> 팀장의 핵심 역할은 모든 일을 직접 처리하는 것이 아니라, 팀이 같은 목표와 기준을 이해하도록 만들고 지연 요소를 조기에 발견해 조정하는 것이다.
