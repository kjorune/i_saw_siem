# 보안로그 기반 사용자 행동 기준선 이상탐지 및 내부정보 유출 위험 스코어링 시스템

보안 로그에서 사용자별 평소 행동 기준선을 만들고, 기준선을 벗어난 행동을 탐지하여 내부정보 유출 위험점수와 조사 우선순위를 제공하는 프로젝트입니다. 위험점수는 실제 유출자를 확정하는 값이 아니라 보안 담당자가 먼저 확인할 사용자를 선별하는 지표입니다.

## MVP 범위

| 구분 | 데이터 | 적용 범위 |
|---|---|---|
| 핵심 | Email | 외부 수신자, 첨부파일, 메시지 크기, BCC, 발송 시간, 신규 대상 및 반복 전송 분석 |
| 핵심 | LDAP | 사용자·조직 정보 연결, 등록 이메일 기반 발신자 확인, 내부·외부 주소 구분 |
| 미정 | File | Email 분석 결과와의 연계 여부를 데이터 품질과 일정에 따라 별도 결정 |
| 미정 | Device | USB·장치 행동의 연계 여부를 데이터 품질과 일정에 따라 별도 결정 |

MVP의 기본 분석 단위는 사용자×일(User×Day)이며, Email과 LDAP만으로 기준선 생성부터 이상도·위험점수·순위·근거 제공까지 전체 흐름을 먼저 완성합니다. File과 Device는 현재 필수 범위에 포함하지 않습니다.

## 디렉터리 구조

```text
00_프로젝트관리/ # 운영 규칙, 체크리스트, 라벨링 정책, 디자인 명세
01_프로젝트기획/ # 프로젝트 및 MVP 기획 문서
02_자료조사/     # 데이터 사전, 사례 및 기술 조사
03_데이터분석/   # EDA, 분석 보고서, 위험지표 근거
04_회의록/       # 회의록과 회의 녹취
05_코드/         # 재실행 가능한 분석·문서·프레젠테이션 생성 코드
06_산출물/       # 최신 분석 결과, 보고서, 발표자료, 검증 결과
07_데이터/       # 원본 및 가공 데이터
```

각 번호 폴더의 최상위에는 최신본을 두고, 명확한 이전 버전은 해당 폴더의 `이전버전/`에서 관리합니다.

## 실행 방법

- 이메일 이상탐지 분석: `05_코드/이메일_이상탐지_분석.py`
- 통합기획서 PDF 생성: `05_코드/통합기획서_PDF_생성.py`
- 위험점수 프레젠테이션 생성: `05_코드/위험점수_프레젠테이션_생성.mjs`

각 스크립트의 로컬 데이터 및 도구 경로는 실행 환경에 맞게 확인해야 합니다.

## 저장소 관리 원칙

- 파일명은 내용을 식별할 수 있는 한글과 밑줄을 기본으로 사용합니다.
- 날짜가 필요한 파일은 `YYYYMMDD`, 버전이 필요한 파일은 `vNN` 형식을 사용합니다.
- 상시 수정하는 작업 원본은 Git 커밋으로 관리하고, 공식 검토본·현행본·제출본에만 날짜와 버전을 부여합니다.
- 공식 상태명은 `작업본`, `검토본`, `현행본`, `제출본`만 사용합니다.
- 공식 산출물은 작성자·검토자·변경 내용·관련 커밋을 산출물 버전 기록에 남깁니다.
- 원본 데이터, 압축본, 임시 렌더링 파일과 의존성 폴더는 커밋하지 않습니다.
- 팀원은 당일 작성한 문서와 산출물을 Slack으로 공유합니다.
- 권순성은 하루 동안 공유된 자료를 확인해 파일명·버전 규칙을 적용하고 GitHub에 반영합니다.

## GitHub 작업 흐름

```text
팀원 작업
→ Slack으로 문서·산출물 공유
→ 권순성 검토 및 파일명·버전 확인
→ Issue·작업 Branch 정리
→ Commit·Push
→ Pull Request 검토
→ main 병합
```

- `main`에는 검토가 끝난 안정 버전만 유지합니다.
- 커밋 하나에는 한 가지 목적의 변경만 포함합니다.
- 개인정보, 비밀키, 대용량 원본 데이터가 포함되지 않았는지 확인한 후 반영합니다.

| 담당자 | 핵심 역할 | 주요 업무 |

| 김현수 | 점수·시각화 | 위험점수·위험등급 구현, 위험 사용자 순위 및 사용자 상세 화면 구현 |
